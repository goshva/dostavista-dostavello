# Курьерский коннектор Достависта + web-кабинет курьера

Личный инструмент курьера: получает **ваши** данные и **ваши заказы** через HTTP API
(без мобильного приложения), показывает их в собственном web-интерфейсе и
**программно строит маршрут на день**.

```
┌──────────────┐   HTTP/JSON    ┌──────────────────┐   REST    ┌─────────────────┐
│ Dostavista   │ ─────────────► │  коннектор       │ ────────► │ web-кабинет     │
│ API          │  X-CSRF-Token  │  providers/      │           │ src/public/     │
│              │  cookie        │  normalize       │           │ карта + список  │
└──────────────┘                └────────┬─────────┘           └─────────────────┘
                                         │
                                  route.js — оптимизация порядка объезда
                                  (точный Хелд—Карп до 16 точек, дальше эвристика)
```

## 1. Что дала актуализация (главное)

Проверено живыми запросами 2026-11-09.

| Что | Статус |
|---|---|
| **Официальный BAPI для интернет-магазинов** (`/bapi/calculate`, `/bapi/order`, …) из [Google Doc](https://docs.google.com/document/d/1-yjBzfkI9Zb44kkQB_rMcq5pNeLThyD6YbvXR9wl7IY/edit) и PHP-клиента [kstkn/dostavista](https://github.com/kstkn/dostavista) | ❌ **публично недоступен.** `robotapi.dostavista.ru` — DNS-записи больше нет; `/bapi/*` на `dostavista.ru`, `robot.dostavista.ru`, `robotapitest.dostavista.ru`, `partner.dostavista.ru` отдаёт `404` / `{"error":"Not found"}`. `/api`, `/openapi.json`, `/swagger.json`, `/api-docs` JSON не отдают |
| **Курьерско-партнёрский кабинет** `https://partner.dostavista.ru` | ✅ **жив и работает.** SPA `courier-partner-cabinet` + недокументированный JSON API, который **отдаёт профиль курьера и его заказы с координатами** |
| `couriers.dostavista.ru` | это рекрутинговый лендинг на Tilda, не API |
| Мобильное приложение курьера | веб-кабинета для одиночного курьера компания не предлагает; API приложения недокументирован → инструмент `discover` (см. §6) |

**Практический вывод:** чтобы получить «свои заказы как курьера», рабочий путь —
API курьерско-партнёрского кабинета (`provider: partner-cabinet`). BAPI для этого
не подходил и раньше: он отдаёт только заказы, **созданные вашим магазином**.

Подробности: [docs/API-DOSTAVISTA-BAPI.md](docs/API-DOSTAVISTA-BAPI.md),
[docs/API-COURIER-PARTNER.md](docs/API-COURIER-PARTNER.md).

## 2. Быстрый старт

Зависимостей нет — только Node.js ≥ 18.

```bash
# 1. Посмотреть интерфейс на демо-данных (ничего подключать не нужно)
node src/cli.js serve --provider demo
#    → откройте http://127.0.0.1:8787

# 2. Подключить свой аккаунт
copy config.example.json config.local.json     # Windows
#   впишите partnerCabinet.email / .password
node src/cli.js login
node src/cli.js whoami
node src/cli.js orders --date 2026-11-09
node src/cli.js route  --date 2026-11-09 --start 55.7558,37.6173 --gpx day.gpx --csv day.csv

# 3. Поднять свой кабинет на реальных данных
node src/cli.js serve
```

`config.local.json` и `.session.json` — в `.gitignore`. **Не коммитьте их.**

## 3. Команды

| Команда | Что делает |
|---|---|
| `providers` | список провайдеров данных |
| `login` / `logout` | вход и сохранение сессии / забыть сессию |
| `whoami` | профиль и `courier_id` |
| `couriers` | курьеры партнёра |
| `orders --date YYYY-MM-DD` | заказы на дату (активные, отменённые, пропущенные) |
| `route --date … --start lat,lon --end lat,lon` | **маршрут на день**, `--gpx`, `--csv`, `--mode osrm\|haversine` |
| `serve [--port 8787]` | web-кабинет курьера |
| `probe` | какие эндпоинты API отвечают и что возвращают |
| `audit` | проверить карту эндпоинтов против живого сервера (только чтение, с отрицательным контролем) |
| `discover --har captures/flow.har` | разобрать захваченный трафик, найти эндпоинты |
| `bapi-diagnose` | проверить живость задокументированного BAPI |

Общие флаги: `--provider`, `--json`, `--debug`, `--email`, `--password`, `--session <p_session>`.

## 4. Web-интерфейс курьера

`node src/cli.js serve` → `http://127.0.0.1:8787`

* вход (логин/пароль **или** готовая cookie `p_session`, если включена капча);
* выбор даты, курьера, начальной и конечной точки;
* **«Построить маршрут на день»** — оптимизированный порядок объезда;
* метрики: точек, пробег, оценка времени, метод решения (точный оптимум / эвристика);
* карта (Leaflet + OpenStreetMap) с нумерованными точками; при отсутствии интернета
  автоматически рисуется SVG-схема, список продолжает работать;
* по каждой точке: звонок (`tel:`), открыть в Яндекс.Картах, маршрут до точки;
* выгрузка **GPX** (OsmAnd / Organic Maps / Garmin) и **CSV** (Excel, с BOM);
* кнопка «Диагностика API».

Сервер слушает только `127.0.0.1` — в нём живёт ваша сессия.

## 5. Как строится маршрут

1. **Нормализация** — все источники приводятся к одной модели `Order` / `Point`
   (`src/lib/model.js`). Точки из кабинета уже с координатами; если координат нет,
   включается геокодер (Nominatim, с файловым кэшем, по умолчанию выключен).
2. **Остановки** — забор и доставка каждого заказа. Уже посещённые точки выпадают;
   если забор выполнен, его доставка остаётся и **не** блокируется ограничением.
3. **Ограничение предшествования** — забор раньше доставки того же заказа.
4. **Оптимизация** (`src/lib/route.js`):
   * ≤ 16 остановок — **точный оптимум** (Хелд—Карп по подмножествам с учётом
     предшествования), O(2ⁿ·n²);
   * больше — жадный «ближайший доступный» + улучшение переносом (relocate),
     которое не ломает предшествование.
5. **Расстояния** — `haversine × 1.3` (офлайн) либо матрица **OSRM** по дорогам
   (`--mode osrm`, публичный демо-сервер; при ошибке тихий откат на haversine).
6. **Оценка времени** — путь / средняя скорость + обслуживание на точке
   (`routing.averageSpeedKmh`, `routing.serviceMinutesPerStop`).

## 6. Если нужен API мобильного приложения

Веб-кабинета для одиночного курьера у компании нет, а API приложения
недокументирован. Универсальный путь — **один раз записать трафик** и получить
карту эндпоинтов, не привязываясь к APK:

```bash
# mitmproxy на телефоне (сертификат mitmproxy нужно установить на устройство)
mitmproxy --save-stream-file flow.mitm
mitmdump -nr flow.mitm --set hardump=out.har

# либо браузер: DevTools → Network → «Сохранить всё как HAR»

node src/cli.js discover --har captures/out.har
```

Инструмент покажет хосты, заголовки авторизации (секреты маскируются), кандидатов
на «список заказов» и схему их JSON. Дальше есть два варианта: добавить новый
провайдер в `src/providers/` (интерфейс — в `src/providers/index.js`) или сразу
проиграть захват через `--provider har`. Методика: [docs/DISCOVERY-HAR.md](docs/DISCOVERY-HAR.md).

## 7. Конфигурация

`config.example.json` → `config.local.json`. Ключевое:

| Поле | Смысл |
|---|---|
| `provider` | `partner-cabinet` \| `demo` \| `har` \| `bapi` |
| `partnerCabinet.email` / `.password` | учётные данные курьера-партнёра |
| `partnerCabinet.session` | готовая cookie `p_session` (вместо пароля; нужна при капче) |
| `bapi.clientId` / `.token` | для стороны заказчика, если поддержка выдаст рабочий адрес |
| `server.host` / `.port` | web-кабинет (по умолчанию `127.0.0.1:8787`) |
| `routing.distanceMode` | `haversine` \| `osrm` |
| `routing.averageSpeedKmh`, `.serviceMinutesPerStop` | оценка времени |
| `routing.startPoint` / `.endPoint` | старт и финиш по умолчанию |
| `geocoding.enabled` | геокодинг адресов без координат (Nominatim) |

Переменные окружения перекрывают конфиг: `DV_PROVIDER`, `DV_EMAIL`, `DV_PASSWORD`,
`DV_SESSION`, `DV_BASE_URL`, `DV_PORT`, `DV_DISTANCE_MODE`.

## 8. Проверка

### Тесты

```bash
npm test
# или явно:
node --test test/smoke.test.js test/partner-cabinet.test.js test/har-replay.test.js
```

64 теста в четырёх наборах, сеть не требуется:

* **`test/smoke.test.js`** — ядро: нормализация заказов, геометрия, точный и
  эвристический маршрут, соблюдение предшествования, планировщик дня, GPX/CSV,
  провайдеры, разбор HAR, cookie-jar, коды ошибок, очистка заглушек конфига.
* **`test/partner-cabinet.test.js`** — интеграционный набор: поднимается локальный
  **сервер-двойник**, повторяющий протокол `partner.dostavista.ru` (meta csrf-token,
  анонимная cookie `p_session`, конверт ответа, ротация и протухание сессии),
  и через него проходит **полный путь коннектора**: bootstrap → CSRF → вход →
  проверка сессии → заказы → маршрут. Здесь же зафиксированы регрессы:
  анонимная cookie не должна считаться входом, а неудачная попытка входа не должна
  «залипать» в процессе.
* **`test/har-replay.test.js`** — запасной путь: разбор захваченного трафика,
  маскировка секретов, авто-обнаружение эндпоинтов и офлайн-реплей заказов из HAR
  с построением маршрута.
* **`test/audit.test.js`** — аудит карты эндпоинтов: классификация ответов сервера,
  отрицательный контроль (выдуманные пути не должны выглядеть настоящими) и гарантия,
  что изменяющие методы не запрашиваются вообще.

### Проверка интерфейса в настоящем браузере

```bash
npm run ui-check          # демо-данные: маршрут строится, карта и выгрузки работают
npm run ui-check-login    # без авторизации: открывается форма входа, а не тихий сбой
```

Скрипт `tools/ui-check.mjs` поднимает сервер, запускает Chrome/Edge в headless-режиме
и управляет им по DevTools Protocol (зависимостей нет — WebSocket и fetch встроены
в Node). Он **нажимает кнопку построения маршрута** и проверяет: сессию, метрики,
список остановок, порядок «забор раньше доставки», ссылки «позвонить» и «открыть в
картах», карту, выгрузку CSV, а также отсутствие исключений и ошибок в консоли.
Если браузера нет — проверка аккуратно пропускается.

```bash
DV_BROWSER="C:\путь\chrome.exe" node tools/ui-check.mjs   # указать браузер явно
```

### Пример захвата трафика

`samples/example-flow.har` — выдуманный HAR, на котором можно посмотреть работу
`discover` и провайдера `har`:

```bash
node src/cli.js discover --har samples/example-flow.har
node src/cli.js route --provider har --har samples/example-flow.har --match /courier/orders
```

## 9. Если что-то не работает

| Сообщение | Что делать |
|---|---|
| «Не заданы учётные данные…» | Нет `config.local.json` либо в нём заглушки из `config.example.json`. Скопируйте образец и впишите реальные данные. Приложение **не отправляет заглушки** на сервер. |
| «Неверный логин или пароль» | Сервер отклонил вход (`invalid_credentials`). Проверьте пару логин/пароль. |
| «Сессия недействительна» / «Сессия истекла» | Cookie `p_session` протухла. Коннектор попробует войти сам, если заданы логин и пароль; иначе войдите заново. |
| «Сервер требует капчу» | Автоматический вход невозможен. Войдите один раз в браузере и перенесите cookie `p_session` (DevTools → Application → Cookies → `partner.dostavista.ru`) в поле «Войти по cookie сессии». |
| `missing_credentials` / пустой `courier_id` | Профиль не содержит `courier_id`. Посмотрите `node src/cli.js couriers` и укажите `--courier <id>`. |
| Точки без координат в маршруте | Включите `geocoding.enabled` в `config.local.json`. |
| Эндпоинты отвечают ошибкой | `node src/cli.js audit` — проверит, какие маршруты живы и что изменилось (подробности: [docs/API-COURIER-PARTNER.md](docs/API-COURIER-PARTNER.md), раздел 8). |

## 11. Юридическая и этическая рамка

* Инструмент работает **с вашим собственным аккаунтом и вашими собственными
  данными** — это не обход авторизации и не доступ к чужим заказам.
* API курьерско-партнёрского кабинета **недокументирован**. Использование
  недокументированного API может противоречить пользовательскому соглашению
  сервиса; решение и риск — на вас. Возможны изменения на стороне сервиса.
* Не публикуйте `config.local.json`, `.session.json`, cookie `p_session` и HAR-файлы:
  в них ваши учётные данные и персональные данные клиентов (адреса, телефоны).
* Инструмент ничего не создаёт, не отменяет и не меняет в системе Достависты:
  только чтение (в коннекторе есть только read-методы, кроме `login`/`logout`).

### Чего сознательно НЕТ в репозитории

При подготовке материалов обнаружилось, что выгрузка веб-архива по `dostavista.ru`
содержит **чужие учётные ссылки** вида `/cabinet/index/0/auth_token/<hex>` — это
персональные ссылки входа, которые сервис рассылал клиентам по SMS. Публиковать
такое нельзя ни в каком виде.

Поэтому в git не попадает ничего чужого (всё это осталось локально в `local-only/`,
каталог в `.gitignore`):

| Что | Почему не публикуется |
|---|---|
| выгрузка веб-архива | чужие персональные ссылки входа |
| текст документа Достависты по BAPI | чужой документ |
| минифицированный JS кабинета | чужой код, охраняемый авторским правом |
| сырая карта эндпоинтов с фрагментами кода | содержит дословные куски чужого кода |

В репозитории остаются только собственный код, собственные описания API
(факты о протоколе: пути, методы, коды ошибок) и выдуманный пример захвата.

Если вы хотите закрыть и это — удалите `docs/API-COURIER-PARTNER.md` или сделайте
репозиторий приватным.
